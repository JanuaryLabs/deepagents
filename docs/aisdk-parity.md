# AI SDK parity

deepagents exists to fill gaps in the AI SDK. This ledger lists each concept the repo owns and says whether the AI SDK, or a package from the `vercel` or `vercel-labs` GitHub orgs, now covers it.

Checked on 2026-11-26 against `ai@7.0.183` ([vercel/ai@0411a13d](https://github.com/vercel/ai/tree/0411a13df36b20bf6c67c82c1056e99d0e48257b)), every public `@ai-sdk/*` package, and the packages and repositories recorded in [aisdk-parity.snapshot.json](./aisdk-parity.snapshot.json). The repo had `ai@7.0.181` installed; nothing that shipped between the two changes a row. To recheck, run the `aisdk-parity` skill ([.claude/skills/aisdk-parity](../.claude/skills/aisdk-parity/SKILL.md)). Its first step, `node .claude/skills/aisdk-parity/scripts/delta.ts`, lists what shipped since the snapshot.

## Bottom line

- Nothing upstream replaces a whole package. Of the 136 rows checked on 2026-11-26, 4 were `covered`, 40 `partial`, 19 `blocked`, 55 `gap` and 18 `domain`; rows whose code has since been deleted are gone.
- **Delete, because upstream does it:**
  - legacy `createRepairToolCall` and `AgentControls`, and the unexported legacy patterns (the DuckDuckGo search tool, T1, is deleted);
  - inside partial rows: `settleDeniedApprovals` (X13, done), the telemetry redaction except the call and response headers the SDK still passes (C29, done), ChatManager's message queue (G3), the guardrail feature (C5, C6, done), and unused host and demo tools (T3, done).
- **Compose, because upstream owns part:**
  - build the context `Agent` on `ToolLoopAgent` (C1);
  - deliver mailbox input through `experimental_createSteering` (C4);
  - compact Anthropic and OpenAI Responses natively (P1, X6).
- **Kept after a probe:** the MCP plugin's own connect deadline (X24): only it fails startup when a host's connect factory ignores its signal.
- **Blocked:** eve cannot take a host `pg.Pool`, its self-hosted schedules run on one replica, and an eve upgrade strands self-hosted sessions. The Workflow SDK with `@workflow/world-postgres` breaks none of those rules, but the owner ruled Vercel Workflow out on 2026-11-26; pg-boss stays.
- **Still ours, with no upstream equivalent:**
  - the message-graph store with branches;
  - reminders and their predicates;
  - fragment rendering;
  - summarizing compaction for providers without native compaction;
  - token estimation;
  - the multi-process turn queue;
  - the Codex-style agent control plane;
  - subscription providers that deploy;
  - the headless composer.

## Verdicts

- `covered`: upstream does what the row does. Delete ours.
- `partial`: upstream owns part of it. Compose that part and keep the rest.
- `blocked`: upstream covers the concept but breaks a named rule. Keep ours. The rules are:
  - AGENTS.md "Force the deployment into the design";
  - the self-hosted deploy target;
  - Postgres stores take a host `pg.Pool` only;
  - the owner's 2026-11-26 decision against Vercel Workflow.
- `gap`: nothing upstream does it. Keep ours.
- `domain`: not an AI SDK concern.

## Probes

Run on 2026-11-26 against the installed packages:

- **C4 steering:** steered messages reach `prepareStep` as `experimental_steeringMessages` before the model call. A repeated id returns the first outcome, and a run whose model already answered continues.
- **X13 denied approvals:** with `settleDeniedApprovals` made a no-op in memory, the three denial tests in `runtime.integration.test.ts` pass. A partial answer (one denied, one unanswered) through `chat()` also ends `output-denied` on the denied part, set by the SDK: every continuation reconciled as completed has run the SDK.
- **P1 Anthropic compaction:** a compaction block streamed into `chat()` is stored with its signature and sent back as a `compaction` block.
- **C29 telemetry:** with `recordInputs` and `recordOutputs` false, ai hands integrations empty prompts and outputs.
- **C35 just-bash 3.6:** nothing in our sandbox path relies on shell state carrying across `exec()` calls.
