Stores persist embeddings and enable similarity search. The retrieval package includes a SQLite-based store that uses the vec0 extension for efficient vector operations.

## SQLite store

The SQLite store uses [sqlite-vec](https://github.com/asg017/sqlite-vec) for vector operations, providing:

- Cosine distance similarity search
- Efficient K-nearest neighbor queries
- Automatic index management
- Transaction support for consistency

### Import

```typescript
import { SQLiteStore, nodeSQLite } from '@deepagents/retrieval';
```

### Basic usage

```typescript
import { fastembed, nodeSQLite, similaritySearch } from '@deepagents/retrieval';
import { local } from '@deepagents/retrieval/connectors';

// Create store with dimension matching your embedding model
const store = nodeSQLite('./knowledge.db', 384);

const results = await similaritySearch('authentication', {
  connector: local('**/*.md'),
  store,
  embedder: fastembed(),
});
```

### Parameters

```typescript
nodeSQLite(dbName: string, dimension: number)
```

| Parameter   | Description                                             |
| ----------- | ------------------------------------------------------- |
| `dbName`    | Path to SQLite database file (created if doesn't exist) |
| `dimension` | Vector dimension (must match embedding model)           |

## Schema

On each open, the store applies its schema with `@zukhruf/sqlite-drift`. The store updates stale tables, indexes and the trigger. It keeps the rows in `sources` and `documents`.

A new vector dimension makes the store replace `vec_chunks` with an empty table. In the same transaction, the store deletes all sources and their documents. The next ingest reads the connector content and embeds the documents again. To keep the indexes of two dimensions, use one database file for each dimension.

**Source:** `packages/retrieval/src/lib/stores/sqlite/ddl.sqlite.ts`

### sources

Tracks data sources and their expiry:

```sql
CREATE TABLE sources (
  source_id TEXT PRIMARY KEY,
  updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now')),
  expires_at TEXT
) STRICT;
```

### documents

Stores document metadata and content hashes:

```sql
CREATE TABLE documents (
  id TEXT PRIMARY KEY,
  source_id TEXT NOT NULL,
  cid TEXT NOT NULL,
  metadata TEXT, -- JSON blob with arbitrary document metadata
  updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now')),
  FOREIGN KEY (source_id) REFERENCES sources(source_id) ON DELETE CASCADE
) STRICT;
```

### vec_chunks

Virtual table for vector storage and search:

```sql
CREATE VIRTUAL TABLE vec_chunks USING vec0(
  source_id TEXT PARTITION KEY,
  document_id TEXT,
  embedding FLOAT[{DIMENSION}] DISTANCE_METRIC=cosine,
  +content TEXT -- auxiliary payload (not filterable) for reconstruction
);
```

## Store interface

All stores implement this interface:

```typescript
interface Store {
  search: (
    query: string,
    options: SearchOptions,
    embedder: Embedder,
  ) => Promise<SearchResult[]>;

  sourceExists: (sourceId: string) => Promise<boolean> | boolean;
  sourceExpired: (sourceId: string) => Promise<boolean> | boolean;
  setSourceExpiry: (sourceId: string, expiryDate: Date) => Promise<void> | void;

  index: (sourceId: string, corpus: Corpus, expiryDate?: Date) => Promise<void>;
}
```

## Search options

```typescript
interface SearchOptions {
  sourceId: string; // Required: filter by source
  documentId?: string; // Optional: filter by specific document
  topN?: number; // Number of results (default: 10)
}
```

## Search results

`store.search()` returns `content`, `distance`, `document_id`, and `metadata` (`null` when absent). `similaritySearch()` adds `similarity` to each result:

| Field         | Type           | Description                                   |
| ------------- | -------------- | --------------------------------------------- |
| `content`     | string         | The matched text chunk                        |
| `distance`    | number         | Cosine distance (lower = more similar)        |
| `similarity`  | number         | 1 - distance (higher = more relevant)         |
| `document_id` | string         | Source document identifier                    |
| `metadata`    | object or null | Custom metadata from the document, if present |

## Real-world examples

### Basic search

```typescript
import { fastembed, nodeSQLite, similaritySearch } from '@deepagents/retrieval';
import { local } from '@deepagents/retrieval/connectors';

const store = nodeSQLite('./docs.db', 384);

const results = await similaritySearch('error handling patterns', {
  connector: local('**/*.md'),
  store,
  embedder: fastembed(),
});

for (const result of results) {
  console.log(`[${result.similarity.toFixed(2)}] ${result.document_id}`);
  console.log(result.content.slice(0, 200));
  console.log('---');
}
```

### Direct store access

For more control, call the store directly:

```typescript
import { fastembed, ingest, nodeSQLite } from '@deepagents/retrieval';
import { local } from '@deepagents/retrieval/connectors';

const store = nodeSQLite('./direct.db', 384);
const embedder = fastembed();
const connector = local('**/*.md');

// Index content
await ingest({
  connector,
  store,
  embedder,
});

// Search directly
const results = await store.search(
  'authentication middleware',
  { sourceId: connector.sourceId, topN: 20 },
  embedder,
);
```

### Check source status

`sourceExpired()` returns `true` only when the source has an expiry time that has passed. A source without an expiry time returns `false`. With `ingestWhen: 'expired'`, `similaritySearch()` ingests a missing or expired source and skips an existing source whose expiry has not passed.

Set the connector's `expiresAfter` duration in milliseconds to control when the source expires. Each ingestion that indexes a nonempty document refreshes the source expiry, even when the document's content hash is unchanged. In the `'expired'` mode, the next search after expiry ingests the source. No background timer refreshes the source. The default `'contentChanged'` mode ingests on every search.

```typescript
import { nodeSQLite } from '@deepagents/retrieval';
import { local } from '@deepagents/retrieval/connectors';

const store = nodeSQLite('./check.db', 384);
const connector = local('**/*.md');

// Check if source exists
const exists = store.sourceExists(connector.sourceId);
console.log(`Source exists: ${exists}`);

// Check if source is expired
const expired = store.sourceExpired(connector.sourceId);
console.log(`Source expired: ${expired}`);
```

### Multiple stores

Use separate stores for different content types:

```typescript
import { fastembed, nodeSQLite, similaritySearch } from '@deepagents/retrieval';
import { local, pdf, rss } from '@deepagents/retrieval/connectors';

const embedder = fastembed();

// Separate stores for different content
const docsStore = nodeSQLite('./docs.db', 384);
const papersStore = nodeSQLite('./papers.db', 384);
const newsStore = nodeSQLite('./news.db', 384);

// Search documentation
const docsResults = await similaritySearch('getting started', {
  connector: local('docs/**/*.md'),
  store: docsStore,
  embedder,
});

// Search papers
const paperResults = await similaritySearch('transformer architecture', {
  connector: pdf('papers/**/*.pdf'),
  store: papersStore,
  embedder,
});

// Search news
const newsResults = await similaritySearch('AI regulation', {
  connector: rss('https://news.ycombinator.com/rss'),
  store: newsStore,
  embedder,
});
```

### Shared store

Or keep multiple sources in one store. Each search still filters by the connector's `sourceId`:

```typescript
import {
  fastembed,
  ingest,
  nodeSQLite,
  similaritySearch,
} from '@deepagents/retrieval';
import { local, pdf } from '@deepagents/retrieval/connectors';

const store = nodeSQLite('./unified.db', 384);
const embedder = fastembed();

// Index all content into one store
await ingest({
  connector: local('docs/**/*.md'),
  store,
  embedder,
});

await ingest({
  connector: pdf('papers/**/*.pdf'),
  store,
  embedder,
});

// Search the local documentation source
const results = await similaritySearch('machine learning', {
  connector: local('docs/**/*.md'),
  store,
  embedder,
});
```

## Transaction safety

The store uses separate `BEGIN IMMEDIATE` transactions to delete a document's old chunks and insert each batch of up to 32 new chunks. Source and document metadata are written before those transactions. A complete ingestion is not atomic: a failed embedding or later batch can leave partial indexed content.

```typescript
// Chunk deletion and each insertion batch commit separately
await store.index(sourceId, corpus);
```

You can ingest multiple sources into the same store. Each ingestion uses the same transactions as above:

```typescript
// Ingest two sources into one store
await Promise.all([
  ingest({ connector: conn1, store, embedder }),
  ingest({ connector: conn2, store, embedder }),
]);
```

## Content change detection

The store uses content hashes (CID) to detect changes:

```typescript
import { cid } from '@deepagents/retrieval';

const content = 'Hello, world!';
const hash = cid(content);
console.log(hash); // SHA-256 hash
```

When a document's CID changes, its chunks are re-indexed. Unchanged documents are skipped.

## Performance tips

1. **Match dimensions**: Ensure store dimension matches embedding model
2. **Choose a result count**: `store.search()` defaults to 10 results and accepts `topN`; `similaritySearch()` requests 50 results
3. **Separate stores**: Use different stores for unrelated content
4. **Batch operations**: Index multiple sources before searching
5. **Use SSD**: SQLite performance benefits from fast storage
