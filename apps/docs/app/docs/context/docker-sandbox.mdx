import { Tab, Tabs } from 'fumadocs-ui/components/tabs';

The Docker sandbox provides isolated code execution by running commands inside Docker containers. It supports three strategies for creating sandboxes, each suited to different use cases.

## Strategies

<Tabs groupId="strategy" items={['Runtime', 'Dockerfile', 'Compose']}>
<Tab value="Runtime">

Starts a vanilla image and runs an ordered list of installers at container startup. Best for quick experiments and when dependencies change frequently.

```typescript
import { createDockerSandbox, pkg } from '@deepagents/context';

const sandbox = await createDockerSandbox({
  image: 'bash:5.3-alpine3.24',
  installers: [pkg(['curl', 'jq', 'python3'])],
  volumes: [
    {
      type: 'bind',
      hostPath: process.cwd(),
      containerPath: '/workspace',
      readOnly: true,
    },
  ],
  resources: { memory: '512m', cpus: 1 },
});

try {
  await sandbox.run({ command: 'python3 --version' });
} finally {
  await sandbox.dispose();
}
```

**Default image:** `bash:5.3-alpine3.24`

**Installers** are the unit of "put a tool in the container." Built-ins: `pkg([...])`, `urlBinary({...})`, `npm(...)`, `pip(...)`, `githubRelease({...})`. They run in array order and share state (architecture, package manager, idempotent tool ensures) via an `InstallerContext`.

**Package manager detection:** Alpine images use `apk`, Debian-based images (debian, ubuntu, node, python) use `apt-get`. `pkg([...])` picks automatically.

</Tab>
<Tab value="Dockerfile">

Builds a custom image from a Dockerfile. Best for reproducible environments with many dependencies. Uses content-based hashing for automatic image caching — same Dockerfile content means same image tag, so Docker skips the rebuild.

```typescript
import { createDockerSandbox } from '@deepagents/context';

// Inline Dockerfile
const sandbox = await createDockerSandbox({
  dockerfile: `
    FROM python:3.11-slim
    RUN pip install pandas numpy matplotlib
  `,
  context: '.',
  volumes: [
    {
      type: 'bind',
      hostPath: process.cwd(),
      containerPath: '/workspace',
    },
  ],
});

// Or reference a Dockerfile path
const sandbox2 = await createDockerSandbox({
  dockerfile: './Dockerfile.sandbox',
  context: '.',
});
```

**Caching:** The image tag is `sandbox-<sha256-first-12-chars>`. Same Dockerfile content produces the same tag, so subsequent calls skip the build entirely.

**Detection:** Inline vs path is determined by whether the string contains `\n`.

</Tab>
<Tab value="Compose">

Manages multi-container environments using Docker Compose. Best for applications that need databases, APIs, or other services alongside the sandbox.

```typescript
import { createDockerSandbox } from '@deepagents/context';

const sandbox = await createDockerSandbox({
  compose: './docker-compose.yml',
  service: 'app',
});

try {
  // Commands run in the 'app' service
  await sandbox.run({ command: 'node --version' });

  // Can reach other services by name
  await sandbox.run({ command: 'curl http://db:5432' });
} finally {
  // Stops ALL services
  await sandbox.dispose();
}
```

**Volumes:** Must be defined in the compose file itself, not via `volumes`.

**Lifecycle:** `dispose()` runs `docker compose down`, stopping all services.

</Tab>
</Tabs>

## Command timeouts and cancellation

Set `commandTimeout` once on any Docker sandbox strategy to limit every
`run` and `spawn` call in milliseconds:

```typescript
const sandbox = await createDockerSandbox({ commandTimeout: 300_000 });
```

A deadline terminates the command's process group inside the container before
`run` returns exit code `124` or `(await spawn()).wait()` resolves with
`{ exitCode: 124 }`. A per-call `abortSignal` remains separate caller
cancellation: `run` and `wait()` reject with the abort reason once the process
group is gone. An abort is not reported as a timeout.

## Stable container names

Runtime and Dockerfile strategies accept an optional `name` to reuse the same
container across calls:

```typescript
const sandbox = await createDockerSandbox({
  image: 'node:lts-bookworm-slim',
  name: 'analytics-indexer',
  installers: [pkg(['curl'])],
});
```

DeepAgents uses `sandbox-<name>` as the Docker container name. Reuse behavior:

- If `sandbox-<name>` is already running, the sandbox attaches to it.
- If it exists but is stopped, the sandbox starts it and attaches.
- If it does not exist, a new container is created.

When attaching to an existing named container, installer execution, volume
preparation, and env setup are skipped because the container is assumed to
already be configured.

`name` must match `/^[A-Za-z0-9_.-]+$/`.

<Callout type="warn">
  `dispose()` still stops (and removes, because runtime and Dockerfile
  containers use `--rm`) named containers even when this call attached to an
  existing one. Coordinate lifecycle if multiple callers share the same `name`.
</Callout>

## Container command overrides

Runtime and Dockerfile strategies accept an optional `command` to control the
container command, with the same behavior as arguments after the image in
`docker run`:

- Omit `command` (default) to append `tail -f /dev/null` as a keep-alive.
- Set `command: null` or `command: []` to append nothing, so the image or
  Dockerfile `CMD`/`ENTRYPOINT` runs as declared.
- Set a non-empty array (for example, `command: ['sleep', 'infinity']`) to
  append arguments verbatim and override image/Dockerfile `CMD`.

```typescript
const sandbox = await createDockerSandbox({
  image: 'node:lts-bookworm-slim',
  command: null, // run the image CMD/ENTRYPOINT directly
});
```

Compose sandboxes do not use this option. Configure command behavior in the
compose file (for example, `command:` or `entrypoint:` per service).

## Engine

The sandbox uses the Docker engine that the Docker CLI selects:
`DOCKER_HOST`, `DOCKER_CONTEXT` and `DOCKER_CONFIG` decide it. To select an
engine without changing `process.env`, pass `environment`:

```typescript
const sandbox = await createDockerSandbox({
  environment: { ...process.env, DOCKER_CONTEXT: 'build-server' },
});
```

Container lifecycle, command execution, and file operations use the Engine API
through `@zukhruf/docker`. Image builds and Compose startup and shutdown use
the Docker CLI, configured to target the same engine.

`environment` selects the engine for this sandbox; `env` sets variables inside
the container. Runtime and Dockerfile strategies validate `name` and `env` keys
before connecting, so invalid input is reported even when the engine is down.

## Runtime flags

Runtime and Dockerfile strategies accept controls equivalent to `docker run`
flags, grouped by concern. Every field is optional. Omitted fields use the
sandbox's defaults where defined, then the image or Docker defaults. For
example, resource limits default to 1 GiB of memory and two CPUs, and the user
defaults to the image's `USER`.

Compose sandboxes do not use these — configure equivalent settings per service in
the compose file.

### Security and isolation — `security`

The sandbox runs untrusted code, so hardening lives in one place:

- `capDrop` / `capAdd` — drop and re-grant Linux capabilities. `capDrop: ['ALL']`
  is the baseline for untrusted code; add back only what a workload needs.
- `readOnly` — mount the root filesystem read-only. Writes then only land in
  `tmpfs` or volume mounts, so pair it with a writable `/workspace` (a `tmpfs`
  entry or a volume) or file writes and the installer phase will fail.
- `tmpfs` — ephemeral, in-memory writable directories, e.g. `['/workspace', '/tmp']`.
- `user` — run as a non-root `uid[:gid]`. The installer phase (`apk`/`apt`/`npm`/
  `pip`) needs root, so non-root suits a pre-baked Dockerfile image rather than the
  runtime-image + installers path.
- `securityOpt` — one `--security-opt` per entry, e.g. `['no-new-privileges']` or
  `['seccomp=/absolute/path/profile.json']`.

```typescript
const sandbox = await createDockerSandbox({
  image: 'bash:5.3-alpine3.24',
  security: {
    capDrop: ['ALL'],
    readOnly: true,
    tmpfs: ['/workspace', '/tmp'],
    user: '1000:1000',
  },
});
```

### Resource limits — `resources`

Cap what a container can consume — important when many agents share a host:

- `memory`, `cpus` — the common limits.
- `memorySwap` — total memory plus swap; set it equal to `memory` to forbid swap
  entirely (otherwise Docker allows up to 2× `memory`).
- `shmSize` — size of `/dev/shm`; raise it for Chromium or ML workloads.
- `pidsLimit` — cap the process count (fork-bomb protection).
- `ulimits` — e.g. `['nofile=1024:2048']`.
- `cpusetCpus`, `cpuShares` — pin or weight CPUs for finer sharing than `cpus`.

### Networking — `network`

- `mode` — `--network`. Use `'none'` for no network at all (strong isolation, but
  it breaks installers that fetch over the network), a custom network name, or
  `'host'` (shares the host stack — defeats isolation).
- `publish` — publish container ports, e.g. `['8080:80']`.
- `dns`, `addHost`, `hostname` — DNS servers, extra `/etc/hosts` entries, and the
  container hostname.

```typescript
const sandbox = await createDockerSandbox({
  network: { mode: 'none' }, // no egress
});
```

### OCI runtime and platform

- `runtime` — `--runtime`. Set a registered runtime such as `'kata-runtime'` to
  back the container with a lightweight VM (its own guest kernel) instead of
  sharing the host kernel. The runtime must be installed and registered in the
  Docker daemon, and the host must have hardware virtualization (`/dev/kvm`); the
  library does not provision it.
- `platform` — `--platform`, e.g. `'linux/amd64'`. Dockerfile sandboxes also pass
  it to `docker build` and fold it into the image-cache key. Docker may emulate
  when it differs from the host architecture.

### Process and devices

- `init` — run an init process as PID 1 that reaps zombie subprocesses.
- `workdir` — working directory inside the container (default `/workspace`).
- `entrypoint` — override the image `ENTRYPOINT`.
- `gpus` — `--gpus`, e.g. `'all'`. Requires the nvidia container runtime on the
  host and is incompatible with a `runtime` such as `'kata-runtime'`.
- `devices` — expose host devices, e.g. `['/dev/fuse']`. Passed through verbatim;
  the library never injects a device implicitly.
- `labels`, `sysctls` — container metadata and kernel parameters as `key=value`.

## Volumes

Attach bind mounts or Docker volumes to the container. Mounts are read-only by
default (`readOnly: true`).

```typescript
const sandbox = await createDockerSandbox({
  volumes: [
    {
      type: 'bind',
      hostPath: '/absolute/path/on/host',
      containerPath: '/workspace',
      readOnly: true, // default
    },
    {
      type: 'bind',
      hostPath: process.cwd(),
      containerPath: '/project',
      readOnly: false, // allow writes
    },
    {
      type: 'volume',
      name: 'existing-dataset',
      containerPath: '/data',
      // lifecycle defaults to 'external': the Docker volume must already exist.
    },
    {
      type: 'volume',
      name: 'sandbox-output',
      containerPath: '/output',
      lifecycle: 'managed',
      readOnly: false,
      // managed volumes are created before container start and removed on dispose.
    },
  ],
});
```

Bind mounts use paths on the Docker daemon's host. For a remote daemon, set
`hostPath` to a path on that machine. DeepAgents leaves the existence check to
Docker. If Docker reports a missing bind source when the container starts,
DeepAgents throws `VolumePathError` with Docker's reported source path and the
configured `containerPath`.

On macOS, Docker Desktop may report `/host_mnt/private/tmp/data` for a configured
`/tmp/data` source. DeepAgents recognizes this form when classifying missing-source
errors; the error's `hostPath` retains Docker's reported path. Keep the macOS
path in the volume's `hostPath` configuration.

External Docker volumes are inspected before the container starts. Managed Docker volumes are created before the container starts and removed on `dispose()` unless `removeOnDispose: false` is set.

Configure cloud storage through Docker volume drivers or filesystems mounted on
the daemon host. Keep S3 or Azure Blob credentials in the host, daemon, or plugin
configuration, then attach the Docker volume with `type: 'volume'` or the host
mount with `type: 'bind'`. For a bucket already mounted with gcsfuse on the daemon
host, `gcs({ hostPath, mountPath })` returns a bind volume. The app can connect to
that daemon remotely.

Managed Docker volumes accept driver-specific settings through `driverOptions`.
Inline credentials can appear in Docker volume metadata; use a preconfigured
named remote to keep credentials out of `docker volume inspect`.

See the [GCS Cloud Storage Volumes recipe](/docs/context/recipes/gcs-cloud-storage)
for remote daemon and Linux host setups, and the
[MinIO / S3 Cloud Storage Volumes recipe](/docs/context/recipes/minio-cloud-storage)
for an rclone connection-string example.

## Environment variables

Set environment variables in the container at creation time. Available to all commands that `run` and `spawn` start.

```typescript
const sandbox = await createDockerSandbox({
  env: {
    NODE_ENV: 'production',
    API_KEY: 'secret-123',
    DB_URL: 'postgresql://user:pass@host/db',
  },
});

const result = await sandbox.run({ command: 'echo $NODE_ENV' });
// stdout: "production"
```

Supported on Runtime and Dockerfile strategies. For Compose, define environment variables in your `docker-compose.yml` under the `environment` key.

Keys are validated — empty keys and keys containing `=` throw a `DockerSandboxError`.

## Command execution APIs

`run` is buffered and returns the output, exactly as the command wrote it, when
the process exits:

```typescript
const result = await sandbox.run({ command: 'python3 --version' });
console.log(result.stdout, result.stderr, result.exitCode);
```

Pass `AbortSignal` to cancel a running command:

```typescript
const controller = new AbortController();
const pending = sandbox.run({
  command: 'sleep 30',
  abortSignal: controller.signal,
});

setTimeout(() => controller.abort(), 1_000);
await pending; // Rejects with the abort reason after the command stops.
```

For live byte streams, use `spawn`:

```typescript
const proc = await sandbox.spawn({
  command: 'python3 long-task.py',
  workingDirectory: '/workspace',
  env: { MODE: 'stream' },
});

const decoder = new TextDecoder();

for await (const chunk of proc.stdout) {
  process.stdout.write(decoder.decode(chunk, { stream: true }));
}

const { exitCode } = await proc.wait();
console.log(exitCode);
```

`spawn` accepts `workingDirectory`, `env`, `abortSignal` and `stdin`. Aborting a
running process rejects `proc.wait()` with the abort reason. `proc.kill()` stops
the process group inside the container, and you can call it more than once.

Set `stdin: true` to write to the process. Closing the stream sends end of file:

```typescript
const proc = await sandbox.spawn({ command: 'cat > /tmp/in.txt', stdin: true });
const writer = proc.stdin.getWriter();
await writer.write(new TextEncoder().encode('hello'));
await writer.close();
await proc.wait();
```

## Installers

Installers are the polymorphic unit that puts a tool inside a running container. Mix and match them in the `installers:` array — they run in order and share an `InstallerContext` (memoised arch, idempotent tool ensures, resolved package manager).

### `pkg([...])` — OS packages

Auto-detects `apk` vs `apt-get` from the image.

```typescript
import { pkg } from '@deepagents/context';

createDockerSandbox({ installers: [pkg(['curl', 'jq', 'python3'])] });
```

### `urlBinary({...})` — pre-built binary from a URL

Architecture-aware via `uname -m`. Supports raw binaries and `.tar.gz`/`.tgz` archives.

```typescript
import { urlBinary } from '@deepagents/context';

createDockerSandbox({
  installers: [
    urlBinary({
      name: 'presenterm',
      url: {
        x86_64: 'https://github.com/.../presenterm-x86_64-linux-musl.tar.gz',
        aarch64: 'https://github.com/.../presenterm-aarch64-linux-musl.tar.gz',
      },
      binaryPath: 'presenterm', // filename inside the archive
    }),
  ],
});
```

`urlBinary` ensures `curl` itself — no need to add it to `pkg([...])` first.

### `npm('<pkg>')` — global npm install

Fails loudly with `MissingRuntimeError` if `nodejs`/`npm` aren't in the image. Pass `{ ensureRuntime: true }` to auto-install them.

```typescript
import { npm } from '@deepagents/context';

createDockerSandbox({
  installers: [
    npm('prettier', { ensureRuntime: true }), // installs node + npm too
    npm('typescript', { version: '5.4.5' }), // pinned version
  ],
});

// Or use a node base image and skip ensureRuntime:
createDockerSandbox({
  image: 'node:lts-bookworm-slim',
  installers: [npm('prettier')],
});
```

### `pip('<pkg>')` — pip install

Same shape as `npm`. `ensureRuntime: true` adds `python3` + the right pip package (`py3-pip` on Alpine, `python3-pip` on Debian).

```typescript
import { pip } from '@deepagents/context';

createDockerSandbox({
  installers: [pip('requests', { ensureRuntime: true, version: '2.31.0' })],
});
```

### `githubRelease({...})` — GitHub release asset

Convenience over `urlBinary` for GitHub releases. The `asset(arch)` callback builds the asset filename per architecture.

```typescript
import { githubRelease } from '@deepagents/context';

createDockerSandbox({
  installers: [
    githubRelease({
      owner: 'mfontanini',
      repo: 'presenterm',
      version: 'v0.15.1',
      name: 'presenterm',
      asset: (arch) => `presenterm-0.15.1-${arch}-unknown-linux-musl.tar.gz`,
    }),
  ],
});
```

### Custom installers

Subclass `Installer` for anything not covered. The base class is a one-method contract.

```typescript
import { Installer, type InstallerContext } from '@deepagents/context';

class CargoInstaller extends Installer {
  readonly kind = `cargo:${this.crate}`;

  constructor(private crate: string) {
    super();
  }

  async install(ctx: InstallerContext) {
    await ctx.ensureTool('cargo');
    const result = await ctx.exec(`cargo install ${this.crate}`);
    if (result.exitCode !== 0) throw new Error(result.stderr);
  }
}
```

## File I/O

Read and write files inside the container. The bytes move through Docker's
archive requests, so binary content is safe:

```typescript
await sandbox.writeTextFile({
  path: '/tmp/data.json',
  content: '{"key": "value"}',
});
await sandbox.writeBinaryFile({
  path: '/tmp/blob.bin',
  content: new Uint8Array([0xff, 0x00]),
});

const content = await sandbox.readTextFile({ path: '/tmp/data.json' });
const bytes = await sandbox.readBinaryFile({ path: '/tmp/blob.bin' });

const stat = await sandbox.stat({ path: '/tmp/data.json' });
const entries = await sandbox.listDirectory({ path: '/tmp' });
const deleted = await sandbox.deleteFile({ path: '/tmp/blob.bin' });
```

A read or a `stat` of a missing path gives `null`. A relative path resolves
against the directory that commands start in. A write onto a directory rejects.
Parent directories are created automatically during writes. The files, and the
directories that a write creates, belong to the container's user: the
`security.user` value, or the `USER` of the image. A process that runs as that
user can change them.

## Container lifecycle

### Manual disposal

Always wrap sandbox usage in `try/finally`:

```typescript
const sandbox = await createDockerSandbox({ installers: [pkg(['curl'])] });
try {
  await sandbox.run({ command: 'curl --version' });
} finally {
  await sandbox.dispose();
}
```

### Auto-disposal with `useSandbox`

```typescript
import { useSandbox } from '@deepagents/context';

const version = await useSandbox(
  { installers: [pkg(['curl'])] },
  async (sandbox) => {
    const result = await sandbox.run({ command: 'curl --version' });
    return result.stdout.split('\n')[0];
  },
);
```

Runtime and Dockerfile containers are configured for automatic removal when
stopped. `dispose()` sends a stop request through the Engine API and resolves
when the engine has removed the container, so its volumes and bind mounts are
free. A container that a named sandbox attached to and that has no automatic
removal stays stopped. Compose sandboxes run `docker compose down` to stop the
stack.

## Error handling

All errors extend `DockerSandboxError`:

| Error                     | When                                                                                                                                                    |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DockerNotAvailableError` | Docker daemon is not running                                                                                                                            |
| `ContainerCreationError`  | Container fails to start                                                                                                                                |
| `PackageInstallError`     | Package installation fails (includes package names, manager type, stderr)                                                                               |
| `InstallError`            | Installer fails. Carries `target` (logical name), `source` (`'url' \| 'npm' \| 'pypi' \| 'github-release'`), `reason` (stderr), `url` (when applicable) |
| `MissingRuntimeError`     | `npm()`/`pip()` ran without `ensureRuntime: true` and the runtime is absent. Carries `runtime` and `required` (binary names)                            |
| `VolumePathError`         | Invalid mount configuration or a bind source Docker reports as missing                                                                                  |
| `VolumeInspectError`      | External Docker volume does not exist or cannot be inspected                                                                                            |
| `VolumeCreateError`       | Managed Docker volume cannot be created                                                                                                                 |
| `VolumeRemoveError`       | Managed Docker volume cannot be removed during cleanup                                                                                                  |
| `DockerfileBuildError`    | Dockerfile build fails (includes stderr)                                                                                                                |
| `ComposeStartError`       | Docker Compose startup fails (includes compose file path, stderr)                                                                                       |

```typescript
import {
  DockerNotAvailableError,
  PackageInstallError,
  createDockerSandbox,
} from '@deepagents/context';

try {
  const sandbox = await createDockerSandbox({
    installers: [pkg(['nonexistent-package'])],
  });
} catch (error) {
  if (error instanceof DockerNotAvailableError) {
    console.error('Start Docker first');
  } else if (error instanceof PackageInstallError) {
    console.error(`Failed packages: ${error.packages.join(', ')}`);
    console.error(`Package manager: ${error.packageManager}`);
  }
}
```
