---
title: chat()
description: Streaming orchestration that persists messages, generates titles, tracks usage, and handles errors
---

The `chat()` function is the high-level streaming entry point for conversations. It wires together message persistence, title generation, usage tracking, and error formatting into a single call that returns a `ReadableStream` of UI message chunks.

```typescript
import { groq } from '@ai-sdk/groq';
import { InMemoryFs } from 'just-bash';

import {
  ContextEngine,
  SqliteContextStore,
  agent,
  chat,
  createBashTool,
  createVirtualSandbox,
  role,
  user,
} from '@deepagents/context';

const sandbox = await createBashTool({
  sandbox: await createVirtualSandbox({ fs: new InMemoryFs() }),
});
const store = new SqliteContextStore('./chat.db');
const context = new ContextEngine({
  store,
  chatId: 'chat-001',
  userId: 'user-001',
}).set(role('You are a helpful assistant.'));

const myAgent = agent({
  name: 'assistant',
  sandbox,
  context,
  model: groq('gpt-oss-20b'),
});

await context.continue(user('Hello'));
const stream = await chat(myAgent, {
  generateTitle: true,
});
```

## Function signature

```typescript
async function chat<TOOLS extends ToolSet>(
  agent: ChatAgentLike<TOOLS>,
  options?: ChatOptions<TOOLS>,
): Promise<ReadableStream<UIMessageChunk>>;
```

The return value is a `ReadableStream` produced by the AI SDK's
`createUIMessageStream()`. It emits UI message chunks such as `text-delta`,
`tool-input-available`, and `data-chat-title` for the client to consume.

The signatures below abbreviate the conditional tool-context types. If a tool
requires context, the options object and its `toolsContext` entry are required.

| Argument  | Type                   | Description                                                                          |
| --------- | ---------------------- | ------------------------------------------------------------------------------------ |
| `agent`   | `ChatAgentLike<TOOLS>` | An object with `stream()`, `context`, and optionally `model`                         |
| `options` | `ChatOptions<TOOLS>`   | Optional tool contexts, title, transform, error-handling, and metadata configuration |

The function throws if:

- The agent has no `context` attached
- The context head is not the assistant placeholder reserved by `context.continue()`

## ChatAgentLike

Any object that satisfies this interface can be passed to `chat()`. The `agent()` wrapper from `@deepagents/context` implements it automatically.

```typescript
interface ChatAgentLike<TOOLS extends ToolSet> {
  context?: ContextEngine;
  model?: AgentModel;
  sandbox: AgentSandbox;
  tools?: TOOLS;
  stream(options?: ChatOptions<TOOLS>): Promise<ChatStreamResult>;
}

interface ChatStreamResult {
  toUIMessageStream(
    options?: UIMessageStreamOptions<UIMessage>,
  ): ReadableStream<UIMessageChunk>;
  readonly result: {
    readonly usage: PromiseLike<LanguageModelUsage | undefined>;
  };
}
```

| Property   | Type            | Required | Description                                                              |
| ---------- | --------------- | -------- | ------------------------------------------------------------------------ |
| `context`  | `ContextEngine` | Yes      | The context engine scoped to the current chat                            |
| `model`    | `AgentModel`    | No       | Required for AI-generated titles. If absent, only static titles are used |
| `sandbox`  | `AgentSandbox`  | Yes      | Sandbox passed to context resolution by the agent                        |
| `stream()` | Function        | Yes      | Resolves context and returns a `ChatStreamResult`                        |

## ChatOptions

```typescript
interface ChatOptions<TOOLS extends ToolSet> {
  onStream?: (writer: UIMessageStreamWriter) => void;
  toolsContext?: InferToolSetContext<TOOLS>;
  transform?: StreamTextTransform<ToolSet> | StreamTextTransform<ToolSet>[];
  abortSignal?: AbortSignal;
  generateTitle?: boolean;
  onError?: (error: unknown) => string;
  messageMetadata?: UIMessageStreamOptions<UIMessage>['messageMetadata'];
  finalAssistantMetadata?: (
    message: UIMessage,
  ) =>
    | Record<string, unknown>
    | undefined
    | Promise<Record<string, unknown> | undefined>;
}
```

| Option                   | Type                                                       | Default                      | Description                                                                                 |
| ------------------------ | ---------------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------- |
| `toolsContext`           | `InferToolSetContext<TOOLS>`                               | `undefined`                  | Required only when a tool declares context; keyed by tool name                              |
| `transform`              | `StreamTextTransform`                                      | `undefined`                  | Custom stream transforms forwarded to `agent.stream()`                                      |
| `abortSignal`            | `AbortSignal`                                              | `undefined`                  | Signal to cancel the stream, forwarded to `agent.stream()`                                  |
| `onStream`               | `(writer: UIMessageStreamWriter) => void`                  | `undefined`                  | Write custom data chunks before title generation and the first model request                |
| `generateTitle`          | `boolean`                                                  | `false`                      | Enable AI-powered title generation for untitled chats                                       |
| `onError`                | `(error: unknown) => string`                               | Built-in formatter           | Custom error-to-string formatter for stream errors                                          |
| `messageMetadata`        | `UIMessageStreamOptions<UIMessage>['messageMetadata']`     | `defaultChatMessageMetadata` | Attaches finish reason and usage at step end, and finish reason and total usage at turn end |
| `finalAssistantMetadata` | `(msg: UIMessage) => Record<string, unknown> \| undefined` | `undefined`                  | Async callback to attach metadata to the final assistant message before persisting          |

`chat()` also forwards `onStart`, `onStepStart`, `onStepEnd`, and `include`
to `agent.stream()`. See the [AI SDK docs](https://ai-sdk.dev) for UI message
stream options, including the `messageMetadata` callback.

## Message persistence flow

The caller reserves the assistant message before `chat()` starts. The stream
then persists intermediate and final assistant state:

```
1. Before streaming  ─── caller uses context.continue() to append input and reserve the assistant
2. On each step      ─── save intermediate assistant state
3. On finish         ─── save final assistant message + track usage
```

### 1. Initial save

Before calling `chat()`, call `context.continue(input)`. It appends the input and
reserves the assistant placeholder that `chat()` updates. This explicit
precondition keeps message ownership in `ContextEngine`.

### 2. Step-finish saves

After each streaming step completes (for example, after a tool call),
`chat()` passes the intermediate assistant message to
`context.writeAssistantSegment()`. Completed steps remain saved if a later
step is interrupted.

### 3. Final save

When the stream finishes:

1. Unfinished tool parts are sanitized if the stream was aborted
2. The `finalAssistantMetadata` callback attaches custom metadata, if provided
3. `context.writeAssistantSegment()` saves the final assistant message
4. `context.trackUsage()` records usage when the model returned it

`writeAssistantSegment()` updates the reserved assistant message in place.
When a reminder splits a turn, it writes to the current assistant segment.
Streaming updates do not each create a new branch.

## Title generation

`chat()` handles title generation automatically for untitled chats:

```typescript
const stream = await chat(myAgent, {
  generateTitle: true,
});
```

When `generateTitle: true` and the agent has a `model`, `TitleGenerator.ensure()`
asks the model for a 2–5 word title. If that call fails, it uses the first user
message's text, truncated to 100 characters with `...` appended when needed.
When `generateTitle` is `false` (the default) or the agent has no model,
`TitleGenerator.ensureStatic()` uses that fallback directly.

Title generation and `agent.stream()` start concurrently. `chat()` waits for
both before merging the model's UI message stream. A new title is saved with
`context.updateChat()` and sent as
`{ type: 'data-chat-title', data: title, transient: true }` for the client to
display. An existing title is left unchanged.

## Error handling

The built-in error formatter converts common AI SDK errors into user-friendly strings:

| Error Type              | Message                                                                       |
| ----------------------- | ----------------------------------------------------------------------------- |
| `NoSuchToolError`       | "The model tried to call an unknown tool."                                    |
| `InvalidToolInputError` | "The model called a tool with invalid arguments."                             |
| `ToolCallRepairError`   | "The model tried to call a tool with invalid arguments, but it was repaired." |
| `APICallError`          | "Upstream API call failed with status `{code}`: `{message}`"                  |
| Other `Error` instances | "An error occurred."                                                          |
| Other values            | JSON-serialized value                                                         |

Override with a custom formatter:

```typescript
const stream = await chat(myAgent, {
  onError: (error) => {
    if (error instanceof MyCustomError) {
      return 'Something went wrong. Please try again.';
    }
    return 'An unexpected error occurred.';
  },
});
```

## Complete example

```typescript
import { groq } from '@ai-sdk/groq';
import { InMemoryFs } from 'just-bash';

import {
  ContextEngine,
  SqliteContextStore,
  agent,
  chat,
  createBashTool,
  createVirtualSandbox,
  role,
  user,
} from '@deepagents/context';

const store = new SqliteContextStore('./chat.db');
const sandbox = await createBashTool({
  sandbox: await createVirtualSandbox({ fs: new InMemoryFs() }),
});

async function handleUserMessage(
  chatId: string,
  userId: string,
  message: string,
) {
  const context = new ContextEngine({
    store,
    chatId,
    userId,
  }).set(role('You are a helpful assistant.'));

  const myAgent = agent({
    name: 'assistant',
    sandbox,
    context,
    model: groq('gpt-oss-20b'),
  });

  await context.continue(user(message));
  const stream = await chat(myAgent, {
    generateTitle: true,
    finalAssistantMetadata: async (message) => ({
      completedAt: Date.now(),
    }),
  });

  return stream;
}
```

## chat() vs agent.stream()

|                     | `chat()`                                          | `agent.stream()`                       |
| ------------------- | ------------------------------------------------- | -------------------------------------- |
| Message persistence | Assistant is automatic after `context.continue()` | Manual                                 |
| Title generation    | Built-in with `generateTitle` option              | Manual                                 |
| Usage tracking      | Automatic via `trackUsage()`                      | Manual                                 |
| Error formatting    | Built-in with override option                     | Set `onError` on `toUIMessageStream()` |
| Return type         | `ReadableStream<UIMessageChunk>`                  | `AgentStream`                          |
| Branch management   | Handles `branch: false` for in-place updates      | N/A                                    |

Use `chat()` when building a conversation UI. Use `agent.stream()` directly when you need lower-level control over the streaming pipeline.
